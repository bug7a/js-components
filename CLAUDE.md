## What this is

**JS-Component Suite**: a set of UI components, samples and app templates built on **basic.js** (`basic/basic.js`). basic.js is a small, dependency-free library by Bugra Ozden where the whole UI is built in plain JavaScript. It creates DOM objects directly, so there is no HTML markup, no CSS authoring and no virtual DOM. It is licensed under Apache 2.0.

There is **no build system, package.json, bundler, linter or test runner**. Every page is a standalone `.htm` file that loads scripts with `<script src>`. To run a page, open it in a browser. The VS Code Live Server extension is configured on port 5505 (`.vscode/settings.json`).

## Core basic.js concepts

- **Startup**: when the page loads, basic.js creates the global `page` (a `MainBox`) and then calls the global `start()` if one exists. Older pages use `window.onload = function(){...}` instead. If a global `loop()` is defined, it runs every 1000 ms (change the interval with `setLoopTimer(ms)`).
- **Constructors**: `Box`, `Label`, `Button`, `Input` (TextBox) and `Icon` (Image). Positional arguments are `(left, top, width, height)`, and an optional props object comes **last**, for example `Label({ text: "Hi", fontSize: 16 })` or `Box(0, 0, "100%", "100%", { color: "red" })`. `obj.props({...})` applies props after creation. The underlying DOM element is `obj.elem`.
- **`that`**: the most recently created object. Code commonly styles it right after creating it (`that.elem.style.whiteSpace = "nowrap"`). `prevThat` is the object created before it.
- **`page` never scrolls** (`basic.css` sets `body { overflow: hidden }`). If a page's content can be taller or wider than the screen, put it inside a full-screen `Box` and turn on that Box's scrolling. Don't try to make `page` or `<body>` scroll:
  ```js
  startBox(0, 0, "100%", "100%", { color: "transparent", scrollY: 1 }); // scrollX: 1 for horizontal
      VGroup({ width: "100%", height: "auto", align: "center top", gap: 20, padding: 40 }); // height "auto" so content can exceed the Box
          // ... page content
      endGroup();
  endBox();
  ```
  Sample and template pages that stack content vertically must follow this rule (see `02-comp-examples/check-box-1.htm`).
- **Only a Box holds other objects.** `Box`, `startBox()` and the groups (`AutoLayout`/`HGroup`/`VGroup`, which are boxes too) can contain children. `Button`, `Label`, `Input` and `Icon` can not: an object created inside a button also bubbles its mouse events to the button, so the button's hover effect fires (it broke the passive-state graying of the `Form` send button). Put an overlay in the same box as a sibling, with `position: "absolute"`, and copy the target's left/top/width/height (see `box.btnSendCover` in `comp/form.js`).
- **Implicit containers**: new objects are added to the current default container. `startBox()`/`endBox()` and `AutoLayout`/`HGroup`/`VGroup` … `endGroup()` push and pop that container. **Every start call needs a matching end call.** basic.js warns in the console about start calls that were never ended.
- **AutoLayout** (flexbox): props are `flow: "horizontal"|"vertical"`, `align: "left top"` (any combination), `gap`, `padding` (a number or `[x, y]`), `wrap: 1`, `justify` and `hug: 1` (sets width and height to `"auto"`, so the group wraps its content). A group defaults to 100% × 100%. **Use `hug: 1` in new code**; `fit: 1` is the older name for the same thing and still works (`box.hug` and `box.fit` both read 1). Don't "fix" existing pages that use `fit`.
- **Common props**: `color` (background), `textColor`, `border`, `borderColor`, `round`, `opacity`, `visible`, `clickable`, `clipContent`, `scrollY`. Alignment helpers: `center()`, `centerBy(obj)`, `aline(obj, "right", space, "center")`.
- **Events**: `obj.on("click", (self, event) => {})` returns a remover function. Resize handlers use `obj.onResize(fn)` and `page.onResize(fn)`.
- **Motion**: `obj.setMotion("left 0.3s, opacity 0.2s")`, then change the properties.
- **Helpers**: `Black(a)`, `White(a)` (rgba strings), `Alpha(color, a)` (any color made transparent: hex -> rgba, others -> color-mix), `println`, `random`, `basic.storage.save/load` (the global `storage` alias is commented out in basic.js), `waitAndRun(timer, fn, ms)` (debounce), `withPageZoom`. Since v26.10.25 (the user, 2026-10-25) `num`, `str`, `isMobile`, `go`, `twoDigitFormat` are only `basic.num()`, `basic.str()`, `basic.isMobile()`, `basic.go(url)`, `basic.twoDigitFormat()`, and the old globals `createBox`, `createButton`, `createLabel`, `createImage`, `createIcon`, `createInput`, `createTextBox` are gone (use `Box`, `Button`, `Label`, `Icon`, `Input`; the functions stay as `basic.createBox()`...): a page or a copied component written for an older basic.js that calls them needs that change.

## How the code reads: `context/basic-js-code-rules.md` (the user, 2026-10-23)

Code written with basic.js reads like plain prose, without needing comments to be understood. **Read `context/basic-js-code-rules.md` before writing basic.js code and follow it**: names that say what they do, the props of basic.js instead of `elem.style`, short functions with early returns, one thought per line (no long one-liners, no nested ternaries), comments for WHY only, named numbers, global things through the box. Correctness wins over a rule, with a `// WHY:` line.

## Writing a component (m2/m3 pattern)

**An `animated` param (the user, 2026-10-27):** when a component gets `animated`, its motions follow `context/basic-js-animated-rules.md` (the model: `comp/search-input-v2.js`; a table by kind of component): `animated: 0` changes nothing, no motion at the first view, one duration and curve (0.25s, `cubic-bezier(0.2, 0.8, 0.2, 1)`), only `transform` / `opacity` / inset `box-shadow`, CSS transitions, off with `prefers-reduced-motion`, one state + `paintMotion()`.

Follow `_component-template.js` or a component file such as `comp/smart-button.js`:

```js
"use strict";
const MyCompDefaults = { width: 240, height: 70, labelText: "", onClick: function (self) {}, style: { box: {}, label: {} } };

const MyComp = function (params = {}) {
    mergeIntoIfMissing(params, MyCompDefaults);   // deep-fills missing keys (mutates params)
    let box = startObject(params);                // container box; children created below go inside it

    // *** PRIVATE VARIABLES / FUNCTIONS
    // *** PUBLIC VARIABLES / FUNCTIONS  → box.setX = function (v) { box.x = v; box.child.text = v; };
    const superRemove = box.remove;               // the component cleans itself in remove(); box.superRemove = superRemove;
    box.remove = function () { if (!box) return; /* clean global events here */ superRemove.call(box); box = null; };

    // *** OBJECT VIEW  → build children (box.label = Label({...}), groups, etc.)
    // *** OBJECT INIT CODE  → box.on("click", ...), initial setters
    return endObject(box);                        // closes the container and makes `that` === box
};
```

- Style packages (`styleName`, `Comp.styles`): the first line is `basic.applyStylePackage(params, Comp.styles, CompDefaults);` (basic.js v26.10.24; it copies `params.style`, so `style: Comp.styles.dark` never changes the package; since v26.10.27 a package with its own `style` key is a package of params: its `style` goes into the style, its other keys fill the params, so a package can change an icon file outside the style; comp-m2 `InputB` (`classic`, `dark`, `ozden` = the fields of `__projects/contact-form`, `ozdenDark` = the contact form of `__projects/webpage-admin-panel`; sample `input-b-ex7-ozden.htm`; EmailInputB, PhoneInputB, TextareaB take them too) and `SearchInput` (`search-input-v2.js`: `classic`, `ozden`, `ozdenDark`, the user's own packages; sample `search-input-v2-ozden.htm`, made for basic-designer; `animated: 1` (2026-10-27): small hover / focus / clear-icon motions with transform, opacity and an inset box-shadow line only, a small pulse of the search icon at every typed letter, nothing at the first view, off with prefers-reduced-motion, `setAnimated()`; off by default in every package, `ozden` / `ozdenDark` too (the user, 2026-10-27)) mark their flat packages with `style: {}`), then `mergeIntoIfMissing(params, CompDefaults)`. every comp-m4 component with style packages and the template use it (2026-10-25); comp-m2 / comp-m3 (`CheckBox`, `RadioButton`) keep their three lines until they are touched.
- `startObject(defaults, params)` (the two-argument form used in `input-b.js`) does the same merge. Params take precedence over defaults in both forms.
- `remove()` (basic.js v26.09.17+) also removes every basic.js object inside the removed object, parents first, and calls their `destroy()` first when they have one. **A component never defines `destroy()`: it overrides `remove()`** — `const superRemove = box.remove; box.superRemove = superRemove;` then `box.remove = function () { if (!box) return; /* cleanup */ superRemove.call(box); box = null; };`. The call uses the local `superRemove`, because a component that extends this one overwrites `box.superRemove` (`box.superRemove.call(box)` would then call itself forever). So every component is removed like any other object (`comp.remove()`), and the cascade above reaches the override. The cleanup holds what `remove()` can not reach: `window`/`document` listeners, timers, `page.remove_onResize()`, static registries (`RadioButton` groups) and the objects the component created directly on `page` (menus, popups). **Since basic.js v26.10.23 new code uses `box.listenTo(window, ...)`, `box.onPageResize()`, `box.after()` / `box.every()` and `box.own(obj)` instead: `remove()` cleans them, so a new component overrides `remove()` only for something else (a static list, a Chart.js instance); also `box.onHoverChange()`, `box.setFocusRing()`, the props `role` / `aria` / `tabIndex` (instead of `elem.setAttribute`), `basic.isOn()`, `basic.addCss()`, and `createIn()` returns its function's result (see `basic/basic-what-is-new.md`, `_component-template.js`; **comp-m4 was converted on 2026-10-23**: 20 of its 31 components have no `remove()` of their own any more; the 11 that keep one clean only what basic.js can not know (Chart.js, static lists like `Modal.stack` / `Toast.list` / `SidePanel.openedPanel`, `ContextMenu` / `SearchResults` detaching from their targets, the open menu of `PropertyPanel`, the object URLs of `SelectFile`, the iframe page and the observer of `WebView`). So **comp-m4 needs basic.js v26.10.23** (a copy of a comp-m4 file must go with a v26.10.23 basic.js; `tabs.js` needs v26.10.24; `select-time.js`, `select-date.js`, `select-color.js`, `breadcrumbs.js`, `mini-graph-box.js` and `spark-line-box.js` call `basic.num()` / `basic.twoDigitFormat()` / `basic.go()` and `modal.js`, `toast.js`, `chart-box.js` call `basic.resolveTheme()` (their colors are in `X.THEMES`, chosen by the `theme` param; `style` has only the shapes), so they need v26.10.25 (`comp/input-b.js` and `comp/label-editor.js` need v26.10.27: their packages are packages of params; the LabelEditor `dark` package also gives `newLabel` a light text color and its own `colorPalette`), like `comp/text-tabs.js`, `textarea-b.js`, `left-menu.js`, `comp/smart-table.js` and `hold-to-confirm-button.js`). comp-m2 / comp-m3 are converted when they are touched.)** A removed object must not be re-added. All of `comp-m2`, `comp-m3` and `comp-m4` follow this (converted in September 2026; `test/components-test.htm` checks it). The login pages guard with `if (box._isRemoved) return;` and keep `box`, because their login code may remove the page and still call `box.waiting.hide()`. `ScrollBar` (`basic/scroll-bar.js`) and Chart.js instances keep their own `destroy()`.
- Every default value becomes a public property on `box`. After creation, change values through explicit `setX()` methods, not JS getters or setters.
- To inherit from another component, use `startExtendedObject(ParentComp, params)` … `endExtendedObject(box)` (see `comp/email-input-b.js`, which extends `InputB`).
- Name components in PascalCase with a matching `XxxDefaults` object. Put component assets in a sibling folder with the same name (`comp/smart-table/*.png`).
- Files keep the house header comment (`/* Bismillah */`, name/version, developer). Comments mix English and Turkish. Keep the existing section markers (`// *** PUBLIC FUNCTIONS:`, `// BOX:`, `// LABEL:`, …).

## Conventions and gotchas

- **A search box (the user, 2026-10-27):** when a page or project needs a search input, use `comp/search-input-v2.js` (`SearchInput`) with `styleName: "ozden"` (light page) or `"ozdenDark"` (dark page), the user's own packages. Not a hand-made search box, not the comp-m1 ones. Existing pages are switched only when asked. A result list under it: `comp/search-results.js`.
- **The newest component is the default (the user, 2026-10-29):** when two components do the same job, new pages and projects use the newest one. The old file has a `NOT FOR NEW PROJECTS` note at the top of its header naming the one to use (`grep -l "NOT FOR NEW PROJECTS" comp/*.js` lists them). Their catalog entries say "Not for new pages: use X" (`index/catalog.js` en / tr and the `<noscript>` list of `index.htm`). A new component that replaces an old one gets the same three steps. **2026-10-31 (the user): the noted ones were archived** (`__archive/components-old-2026-10-31/`: comp-m2 `dialog`, `text-tabs`, `tiny-table`, `login-page`, `badget`, `ui-effects`, `ui-standards`, comp-m4 `modal`, and comp-m2 `waiting` (use `comp/loading-screen.js`)); the pages that used them were moved to the new ones first. **Parallel designs are kept on purpose (the user, 2026-10-31):** some components do the same job with a different design or a more practical use, and both go on: `comp/tiny-select.js` / `comp/select-box.js`, `comp/full-screen-select.js` / `select-box.js` (`fullHeightList`), `comp/slider.js` / `comp/slider-field.js`, `comp/line-progress-bar.js` / `comp/progress-bar.js`, `comp/smart-table.js` (very many rows) / `comp/data-table.js`, `mini-graph-box.js` / `spark-line-box.js`, `toast.js` / `notice.js`. Do not merge or retire them without asking.
- **A bubble / tooltip (the user, 2026-10-30):** `comp/tooltip.js`: `Tooltip({ target, hintText })` follows the mouse; `Tooltip.show(target, text, look, side)` puts a bubble at an object (returns it, `.remove()`). Both: an optional arrow (`lbl_arrow` / `look.arrow`) whose edge goes on from the edge of the bubble (`lbl_border` / `look.border`), and the bubble never leaves the screen (it slides in, or goes to the other side). The look keys: `Tooltip.BUBBLE_LOOK` (`look` param of `Tooltip()` over its `lbl_` ones). `content: function (bubble) {}` builds your own objects in the bubble (one under the other, `contentGap`); `trigger: "click"` / `Tooltip.openPopover(target, content, look, side, text, { onClose })` is a popover: it stays, its content can be clicked, a click outside / Escape (window capture: it does not reach a Dialog) / a second click closes it, one at a time (`Tooltip.closePopover()`, `isPopoverOf()`), placed again on resize. Samples `02-comp-examples/tooltip-2.htm` (the bubble) and `tooltip-3.htm` (content, popover). A new bubble or popover uses it, not a hand-made one.
- **A dialog (the user, 2026-10-29):** new pages and projects use `comp/dialog.js` (`Dialog`; `Dialog.confirm` / `alert` / `prompt`). `comp/modal.js` (`Modal`) and the old `comp/dialog.js` were archived on 2026-10-31.
- **Standalone copies**: `./_make-standalone.sh <project-folder>` (2026-10-31, the user: **the project folder is not changed**: a ready copy is made in `_dist/<name>/` (gitignored; made again from scratch at every run, a `_standalone.txt` note in it; a non-empty folder without that note is never cleared), `--out <folder>` elsewhere, `--in-place` the project folder itself (the old behavior, for the sites that live so); the components go into ONE `comp/components.min.js` by default (in the order the pages load them, the icon folders still in `comp/<folder>/`, `basic/` apart; the pages get one `<script>` for it), `--separate` one file each, and a project made in place with one file each keeps that layout; `--list`: only shows) makes a project folder work outside the repo: it reads the `<script src>` / `<link href>` of its `.htm` pages, copies what they load from `basic/` into `<project>/basic/` (`.min` files, `font/`, `LICENSE`) and from `comp/` into `<project>/comp/` (`name.min.js` made from the source with terser, icon folders copied and their paths rewritten to `comp/<folder>/`, origins in `comp/_sources.txt`), and rewrites the page paths. Run it again to refresh the copies. It only lists the paths that leave the folder in the project's own code (a `rootPath: "../../"` in a `config.js`): change those by hand. `03-webpage/webpage-basicjs` and `__projects/webpage-admin-panel` are made standalone with it **in place** (`--in-place`: they live so in the repository, their pages load their own `basic/` and `comp/`) (the admin panel site "Ozden Panel", to be published at `https://bug7a.github.io/ozden-panel/`, has its live demo in `demo/` (the self-contained copy of `js-admin-panel`, see `04-template-m2`); its contact form uses the Form component and a private mail service address, which is why it is kept out of the repository).
- **The components have NO `.min.js` twins (the user, 2026-10-30)**: the 99 twins of `comp-m1`...`comp-m4` were removed, and every page that loaded one (samples, templates, the catalog `index.htm`, `__projects/contact-form`) loads the source now. Pages load `comp/name.js`; a page may still load `basic/basic.min.js` (the library keeps its min files). A component's `.min` file exists only in a copy that leaves the repo: `_make-standalone.sh` makes it from the source (one `.min.js` per component, or all in one `comp/components.min.js` with `--one-file`); the handbook site's `_update-copies.sh` makes its three with terser. Never add a `.min.js` next to a component source. (`comp/chart-box/chart-4.5.1.umd.min.js` is Chart.js itself, not a twin: it stays.)
- **The `.min` twins of the library**: `basic/basic.min.js`, `basic.min.css`, `scroll-bar.min.js` stay (people download them; `_make-standalone.sh` copies them). After you edit one of their sources, rebuild the twin with `./_make-min-js.sh --build basic/basic.js` (no arguments: lists the stale twins and writes nothing; `--build` alone: rebuilds all the stale ones). It works only on `basic/` since 2026-10-30, keeps the `/* Bismillah */` header and never creates a twin. Staleness is read from the file dates, which a fresh clone or a branch change rewrites, so a listed file is not always really stale.
- Template folders may contain **copies** of the library and components, for example `js-admin-panel/common/ui-standards.js` (`todo-app` had an old v1.6.5 `library/` until 2026-10-28; now `04-template-m2/todo-app-example/basic/` is a standalone copy of the current one). Fixing `basic/` or `comp/` does not update those copies.
- Script order matters: load `basic.css` and `basic.js` first, then `ui-standards` if you use it, then the components, then the page code. A component that extends another must load after its parent.
- Paths are relative to the `.htm` file (samples use `../basic/`, templates in `04-template-*/<app>/` use `../../basic/`).
- The current library version is in the `basic/basic.js` header (v26.10.27 at the time of writing; also `basic.version`). Release notes: `__handbook/english/00-what-is-new.md` (and `turkce/`).
- An inline `<script>` in a `.htm` file must not contain a closing tag as plain text (in a string or a comment), even `</body>` or `</head>`: write `<\/body>`. Live Server puts its reload script before the first body end tag in the file; inside a string, its `</script>` closed the page script and the rest of the code was shown as text (`test/components-test.htm`).
- **A box that scrolls uses `scrollY = 1` / `scrollX = 1`, never `overflow` / `overflowY` / `overflowX: "auto"` in `css` (the user, 2026-10-28).** The props also make the box clickable; with raw css the box keeps `pointer-events: none` and the mouse wheel does not scroll it (found in the Tabs panel and the Modal body, 2026-10-28). Each prop sets only its own axis (`overflowY: "hidden"` for the other axis stays in css when needed). Put it after a `css = {...}` that would overwrite it.
- `basic.css` gives every basic.js box `pointer-events: none` and the page `user-select: none`, and both are inherited. A raw HTML element added into a box (for example a `<textarea>`) needs `pointer-events: auto; user-select: text` or it can not be clicked.
- A Box with `height: "auto"` does not grow with basic.js children (they are absolutely positioned). Use a group (`VGroup`/`HGroup`), or set the child wrapper to `position = "relative"`.
- `setDefaultContainerBox(box)` is not part of the start/end stack: after the next `endGroup()` the default container is the stacked parent again, not `box`. To create objects in an existing box (a component's list after creation), use `createIn(box, function () { ... })` (basic.js v26.09.18): it sets the container, runs the function and restores the previous container, also on error. Otherwise set it again before each object you create directly in `box` (see `comp/tag-input.js` chips), or create one wrapper group in it. Children created while a group is hidden (`visible: 0` at create time) are absolutely positioned, not flex items: hide the group after its children are created. Also, `visible: 0` in the props is undone if you set `elem.style.display` afterwards: set the display first, then `obj.visible = 0`. A flex group with `width: "auto"` inside a scrolling Box does not grow with its children (extra children are clipped): give it `width: max-content`.
- **`box.width` / `box.height` never read "auto" or "100%"**: for a text value basic.js gives the measured size (a number; 0 for an "auto" box that is not drawn yet). A component reads such a value from `params` before `startObject()` (`const isAutoHeight = (String(params.height) === "auto")`). A check of `box.height === "auto"` after it was always false: TreeView `height: "auto"` was 0 px high, and the same check was found in ItemList, Breadcrumbs and Tabs (2026-10-26; the Tabs line that made an "auto" bar "fit-content" never worked and was removed: an "auto" bar fills its row, the user's choice).
- **A group clips its content** (every Box and group is `clipContent: 1`, `overflow: hidden`, by default). An object that moves out of its box under the mouse (a button that lifts with `translateY`, a picture that grows with `scale`, a glow or a focus outline) is cut at the edge of a group as high as its content. Give such groups `clipContent: 0` (the user, 2026-10-21: "we meet this often"); keep `clipContent: 1` only where cutting is the point (a picture with round corners, a background image).
- Page and component helpers are global. Do not name them like basic.js globals (`Box`, `Label`, `random`, `println`...; a page `const createButton` once broke `Button()` with infinite recursion; since v26.10.25 the `create*` names are free again). Prefer `MyPage.createButton`.
- Every default value of a component becomes a property on its box, so a default must not be named like a basic.js setter: `html` sets `innerHTML` (it wiped a component's children), `zoom` belongs to the page, `text`, `color`, `title`, `visible`... Use names like `htmlText` or `scale`.
